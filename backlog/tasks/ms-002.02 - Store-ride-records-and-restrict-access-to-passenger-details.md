## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The current site holds trip data in the form and in messages. One driver needs a reliable record on more than one device. The static site has no booking service. Hosting, recurring cost and retention remain owner choices.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A ride has a stable reference, source, status, passenger contact, pickup and destination, Paris pickup date and time, passenger count and return details where applicable. Saved records survive reload and a new driver session.
- [ ] #2 Only the signed-in driver can list rides or change their status and schedule. A rider can see only their own booking through private access. Driver notes and other passengers stay private.
- [ ] #3 Supported status changes are enforced on save. Tests show that a repeated request or stale edit cannot duplicate a ride or silently overwrite a newer decision.
- [ ] #4 Record the owner-approved hosting, operating cost, retention and recovery approach before live provisioning.
<!-- AC:END -->
